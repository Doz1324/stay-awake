# Stay Awake / 短时唤醒工具

适用于学习、办公、阅读等不方便走动的场景。任务仅提供短时注意力刺激，不保证消除困意。

## 在线体验

[打开 Stay Awake](https://stay-awake-focus.netlify.app/)

网页用于直接体验，本仓库用于查看源码、在本地运行及参与改进。各地网络可达性可能不同，目前尚未确认大陆手机无代理访问结果。

这是纯前端工具：没有账号、后端、音效或排行榜。所有词库、题目生成和统计计算都在浏览器中完成。每次自动结束，仍困时可按需补充，所有模式共用滚动使用额度。

## 快速开始

下载本仓库后进入项目目录，再按下面的命令安装和运行。macOS 用户完成安装及构建后，也可运行 `zsh ./start-local.command` 启动本地生产预览。

## 标准开发与运行方式（Mac / Windows）

准备 Node.js **24 LTS**（项目最低要求为 22.12）和 npm。安装完成后重新打开终端，用 `node --version`、`npm --version` 检查。无需全局安装 Vite。

```sh
npm install
npm run dev
```

开发地址固定为 **http://127.0.0.1:5173/**。修改源码后自动更新，开发模式不启用离线缓存。

```sh
npm run typecheck
npm test
npm run build
npm run preview
```

生产预览地址固定为 **http://127.0.0.1:4173/**。`build` 会先检查 TypeScript，再生成 `dist/` 和离线缓存脚本。

`localhost` 和 `127.0.0.1`、不同端口、不同浏览器都各自保存数据。**建议日常始终使用 `http://127.0.0.1:4173/`。**开发与生产地址的使用额度和记录互不共享。

### 手机在同一 Wi-Fi 下测试

```sh
npm run dev -- --host 0.0.0.0
```

在手机访问 `http://电脑的局域网IP:5173/`。电脑需保持开机及服务器运行，防火墙需允许访问；部分校园 Wi-Fi 不允许设备互访。此命令将开发服务器开放到局域网，仅在可信网络中使用。

首版支持手机触摸与小屏幕，但不承诺普通局域网 HTTP 的独立离线能力。通过线上 HTTPS 地址完成首次缓存后，可在支持 Service Worker 的浏览器中离线使用。

## 功能与操作

| 模式      | 操作                                                       |
| --------- | ---------------------------------------------------------- |
| Boost     | 默认推荐：每 15 秒切换一次快速任务，按所选总时长结束       |
| Capture   | 按 1–9 或点击九宫格中亮起的目标，每题有时限                |
| Switch    | 按方向键或触摸按钮，每四题切换“箭头朝向 / 所在位置”规则    |
| Search    | 从九个相似符号中找出不同项，按 1–9 或触摸选择              |
| Random    | 随机选择一种任务，持续整个 Session                         |
| Reaction  | 等中央按钮变绿，按 Space 或点击；提前点击会重置本轮        |
| Math      | 输入整数答案，Enter 或触摸提交                             |
| Stroop    | 判断字体颜色：R 红、G 绿、B 蓝、Y 黄；也可以触摸按钮       |
| Memory    | 看数字 1 秒，隐藏后输入；从 6 位开始，在 3–10 位之间自适应 |
| Typing    | 按词组逐字符输入，正确完成后自动切换；错误会即时标记       |
| Emergency | 90 秒内五段，每段 18 秒；三种新快速任务混合，避免连续重复  |

- 首页空白处按 **Space** 开始；聚焦选择框或按钮时保留原生键盘行为。
- **Esc** 或“结束本次”立即结束，只按实际使用时间计入额度。
- 普通 Session：30 / 60 / 90 秒，默认 60 秒。
- 所有模式共享 **滚动 10 分钟累计最多 180 秒**；较早的使用时间移出窗口后，额度逐秒恢复，不是额外再锁十分钟。
- 首页与结果页均可选择“仍然困”补充，默认 45 秒，切换到新的快节奏组合，优先避开上一任务。
- 至少需要 30 秒额度才可开始；不足所选时长时，按剩余整秒缩短本次 Session。补充、Emergency、手动选任务使用同一份额度。
- 举例：60 秒首次使用后，可以再用 45 + 45 + 30 秒。累计达到 180 秒后，页面显示恢复到至少 30 秒可用额度的倒计时。任何情况下都不自动接着下一轮。
- 新快速任务连续答对三题缩短单题时限，错误或超时则放慢；局部计时条、140 毫秒反馈，不使用闪屏或音效。原五种任务仍可手动选择。
- 深色为默认，可在“设置 / 统计”切换浅色。
- 今天、近 7 天按本地日历日期统计。跨午夜的 Session 按开始日归属；提前结束记录实际时长。
- Reaction 取有效反应的平均值；其他任务按总作答正确率统计；Typing 按新增字符统计，退格不会抹去已产生的错误。

## 防连续使用机制

统一 `SessionManager` 管理截止时间，任务组件只有输入检查与上报结果的权限。

1. 开始前根据过去十分钟的实际使用区间计算可用额度，持久化本次截止时间；每次最多 90 秒，计时中不额外续时。
2. 每次输入都检查截止时间；切后台、锁屏、休眠不延长时限。浏览器暂停执行期间无法绘制结束页，恢复后会立即按原截止时间结算。
3. Esc、刷新和正常关闭页面会结束 Session，并保留已使用秒数。异常退出时根据已保存的截止时间结算，最多计入原计划时长，不会因睡眠或挂后台而无限增加使用记录。
4. Web Locks 保证同源标签页之间的开始操作互斥，并区分仍活着的页面与已经关闭的页面。
5. 普通局域网 HTTP 不支持 Web Locks 时，使用 IndexedDB 事务串行化状态修改。若页面被异常杀死且没有触发关闭事件，其他页面保守等待原 Session 到期再结算，不允许抢先重开。
6. 修改设置不会清空已使用额度。写入失败或记录格式异常时禁止开始，保留原始数据，不静默清空。

任务强度提高属于产品试验，不保证抵消睡眠不足。实际效果应看结束任务后是否更容易继续学习、办公或阅读、帮助持续多久，而不是仅看任务分数。

这些限制用于个人自律，不是防篡改系统。主动清除存储、换设备或浏览器、篡改脚本或系统时钟仍可绕过。设备之间不做同步。

## 离线使用与更新

首次运行生产版本时需要让页面完整加载。页脚显示“离线已就绪”之后，同一浏览器可在断网时重新打开原地址；也可以收藏该地址。开发模式不提供离线缓存。

- 所有运行资源本地打包，不使用远程字体或 CDN。
- 构建脚本根据文件内容生成版本化 Service Worker，预缓存页面、JS、CSS、图标与清单。
- 新版本缓存安装后，等待所有旧页面关闭才激活，不会在 Session 中强制刷新。
- 更新源码后重新 `npm run build`；联网打开一次让浏览器获取更新，关闭本站全部标签页，再重新打开。
- 浏览器可能清理缓存；无痕浏览、主动清理数据或存储空间不足也可能影响离线能力。以页面显示的缓存就绪状态为准。

## 目录与扩展

```text
src/
  components/    通用显示组件
  pages/         首页、Session、结果、设置与统计
  session/       状态类型、纯逻辑、统一 SessionManager
  tasks/         八种独立任务、注册表、快节奏单题引擎、输入辅助函数
  storage/       localStorage 统一读写、结构校验、跨标签页互斥
  statistics/    日期范围与加权统计
  data/          离线英文素材
  offline/       缓存注册与就绪状态
  styles/        响应式样式和主题
scripts/         离线资源构建
public/          图标与 Web App 清单
tests/           单元测试、浏览器验收
```

新增任务：在 `tasks/catalog.ts` 加入 ID、名称与 `fast` 标记，实现接收 `TaskProps` 的组件，然后在 `tasks/registry.ts` 注册。首页选项、类型与随机池自动更新；Boost、Emergency 与补充从 `fast` 任务中选择。至少保留两种快速任务。SessionManager 不需要修改。所有输入先调用 `canInteract()`，通过 `report()` 上报；定时器在卸载时清理。

存储键继续使用 `stay-awake:v1` 以保留现有历史，内部数据格式升级到 `version: 2`。旧版设置和记录自动迁移，旧 `cooldownUntil` 与冷却配置删除；旧 Random 默认升级为 Boost，手动选择的模式和主题保留。进行中的旧 Session 保留原截止时间以便结算。记录包括实际起止时间、表现与最后任务，滚动额度实时计算。数据仍只在浏览器中，`node_modules/` 与 `dist/` 均不提交 Git。

浏览器支持可选 WebMCP API 时，注册只读的 `read_wake_up_status`；它无法开始任务、代答或增加额度。不支持该 API 的浏览器不受影响。

## 检查与测试

```sh
npm run typecheck
npm test
npm run build
npm run format:check
```

浏览器测试需要本机 Chrome，并先在另一个终端运行 `npm run preview`：

```sh
npm run test:e2e
```

测试在独立、临时的浏览器环境执行，不会更改日常浏览器里的统计与额度。验证截止时间、三分钟滚动上限、部分区间回收、补充与缩短、旧数据迁移、标签页并发、八种任务交互及离线重开。截图与失败诊断输出到 `test-results/`。

`npm run format` 用于统一源码排版。

## 发布与贡献

项目使用 React、TypeScript 和 Vite，运行时不依赖 Netlify 或 GitHub API。Netlify 构建命令为 `npm run build`，发布目录为 `dist`，配置见 `netlify.toml`；也可把 `dist` 部署到其他静态托管服务。

当前线上站采用手动上传，提交代码到 GitHub 不会自动更新线上网页。不同网址的使用记录、额度和反馈独立保存在各自浏览器中，不上传到此仓库，也不跨设备同步。

欢迎通过 Issues 反馈问题，附上浏览器、设备和复现步骤；也欢迎提交 Pull Request。请不要在问题中上传密码、访问令牌或个人使用记录。改进请继续保留自动结束、滚动额度和低干扰设计，不加入排行榜、连胜或无限续玩。
